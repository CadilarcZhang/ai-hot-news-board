# 浏览历史功能设计文档 (localStorage 方案)

> 版本：v1.0
> 更新日期：2026-02-09

## 1. 背景

原浏览历史功能存在以下问题：
1. 数据存储在服务端内存中，重启丢失
2. 所有用户共享同一份数据，隐私泄露
3. 无用户身份隔离

新方案改用 localStorage 实现，数据保存在用户浏览器本地。

## 2. 功能需求

| 功能 | 描述 |
|------|------|
| 自动记录 | 点击热搜时自动保存到浏览历史 |
| 历史列表 | 显示已浏览的新闻列表 |
| 删除历史 | 支持删除单条历史记录 |
| 查看内容 | 点击历史记录查看 AI 生成内容 |
| 本地存储 | 数据保存在浏览器 localStorage |

## 3. 数据结构设计

### 3.1 存储格式

```javascript
// localStorage key: hot_news_history
{
  "hot_news_history": [
    {
      "id": "unique-id",
      "title": "热搜标题",
      "heat": "热度值",
      "platform": "weibo/toutiao/douyin",OK，可以先不保留 content
      "browseTime": "2026-02-09T12:00:00.000Z",
      "content": { ... }  // 可选，保存当时的 AI 内容
    },
    // ... 最多 15 条
  ]
}
```

### 3.2 字段说明

| 字段 | 类型 | 描述 |
|------|------|------|
| id | string | 唯一标识符，格式：`{timestamp}-{random}` |
| title | string | 热搜标题 |
| heat | string | 热度值 |
| platform | string | 来源平台：weibo/toutiao/douyin |
| browseTime | string | ISO 时间戳，记录浏览时间 |
| content | object | AI 生成内容（可选） |

## 4. 核心 API 设计

### 4.1 常量定义

```javascript
const HISTORY_STORAGE_KEY = 'hot_news_history';
const MAX_HISTORY_ITEMS = 15;  // 最大保存条数
```

### 4.2 方法清单

| 方法 | 功能 | 返回值 |
|------|------|--------|
| `saveToHistory(news)` | 保存浏览记录 | void |
| `getHistoryList()` | 获取历史列表 | Array |
| `deleteHistoryItem(id)` | 删除单条记录 | boolean |
| `clearHistory()` | 清空所有历史 | void |

### 4.3 方法实现逻辑

#### saveToHistory(news)
1. 从 localStorage 获取现有历史
2. 检查是否已存在同标题记录
3. 如果存在，更新其浏览时间（移到顶部）
4. 如果不存在，创建新记录，添加到顶部
5. 超过 15 条时删除最旧的记录
6. 保存回 localStorage

#### deleteHistoryItem(id)
1. 获取历史列表
2. 过滤掉 id 匹配的记录
3. 保存回 localStorage

## 8. 实现要点

| 类别 | 说明 |
|------|------|
| 存储位置 | `localStorage.setItem('hot_news_history', JSON.stringify(history))` |
| 数据去重 | 同标题不重复保存，更新浏览时间 |
| 数量限制 | 最多保存 15 条，自动清理旧数据 |
| 隐私安全 | 数据只在用户本地，服务端不可见 |

## 9. 测试用例

| 用例 | 预期结果 |
|------|----------|
| 点击热搜后切换到历史 Tab | 历史列表显示该条记录 |
| 同一条热搜点击两次 | 只保留一条记录，更新浏览时间 |
| 删除一条历史记录 | 该记录从列表消失 |
| 超过 15 条记录 | 最旧的记录被自动删除 |
| 刷新页面 | 历史记录仍然存在 |

## 10. 优缺点分析

### 优点
- ✅ 数据持久化，重启浏览器不丢失
- ✅ 用户隐私保护，数据只在本地
- ✅ 无服务端资源消耗
- ✅ 实现简单，维护成本低

### 缺点
- ❌ 跨设备不可同步
- ❌ 用户清除浏览器缓存后数据丢失
- ❌ 无法实现跨浏览器/跨设备历史
